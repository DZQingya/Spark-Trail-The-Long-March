# AI 使用说明

## 1. 使用原则

本作品允许 AI 辅助，但不把 AI 生成内容直接当作未经审核的最终作业。代码、玩法、文本和文档均由项目作者在开发过程中检查、运行和修改。历史事实另行查找权威来源，并在 `docs/历史资料来源.md` 中记录机构和链接。

## 2. AI 辅助范围

- JavaScript、Canvas 界面、战斗动画、存档和测试流程建议。
- 控制台交互、随机事件选择、资源结算和自检代码初稿。
- 情景化事件文本草案。
- 作品说明、测试记录和演示流程的结构草案。
- 测试场景与边界条件建议。

## 3. 人工负责范围

最终提交前必须由项目作者本人完成：

1. 确认主题选择和作品定位。
2. 逐条打开并核对历史来源。
3. 修改不符合本人表达习惯或课程要求的文本。
4. 完整试玩至少一局，记录实际用时、路线、选择和结果。
5. 根据试玩体验调整难度和事件权重。
6. 填写姓名、班级、学号和个人创作反思。
7. 对最终提交版本负责。

## 4. 历史内容核验方式

- 遵义会议、四渡赤水、会宁会师：中共中央党史和文献研究院页面正文。
- 长征节点综述：共产党员网页面正文。
- 长征精神的课程关联：共产党员网“党史百问”。
- 90 周年主题背景：中国人民革命军事博物馆、求是网专题。
- 游戏内随机事件明确标为“情景化玩法事件”，不冒充具体战例。
- 不采用没有来源的伤亡数字、具体对话或领导人心理描写。

## 5. 开发过程留存

本项目保留以下材料：

- Git 提交历史与工作区变更。
- `docs/开发记录.md`：功能、数值和问题变化。
- `docs/测试记录.md`：编译、自检、浏览器自动点击回归和人工验收项。
- `docs/历史资料来源.md`：来源、链接、用途和核验记录。
- `docs/作品说明.md`：最终作品说明。
- 代码中的 `--self-test` 和 CTest 自动测试。

## 6. 提交前声明建议

可在作品说明或答辩中如实说明：

> 本作品使用 AI 辅助完成代码脚手架、情景文本草案和文档结构；主题选择、历史来源核验、玩法判断、试玩修改和最终提交由本人负责。AI 生成内容未在未经检查的情况下直接作为历史事实或最终作业提交。

## 7. 仍需本人完成的事项

- [ ] 真人完整试玩并记录用时。
- [ ] 对历史来源做最终签认。
- [ ] 对事件文本和数值做个人化修改。
- [ ] 填写个人信息和创作反思。
- [ ] 录制或截图课堂演示材料。
- [ ] 检查最终压缩包不依赖个人电脑绝对路径。
